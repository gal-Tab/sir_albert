## Decisions + WHY

- **Two stages, not one.** A SessionEnd hook is bash with no LLM and must never block
  teardown (`session-record.sh` already guarantees `exit 0`). Generation + git are moved
  to a batched off-critical-path summarizer. Do NOT put `claude -p` or `git push` in the
  SessionEnd hook.
- **PR-gated, not direct-to-main.** The meetings loop writes direct-to-main, but journals
  are a new, unproven writer into a shared INTERNAL repo → start with branch+PR; graduate
  to direct-append only after the format is trusted (a documented follow-up).
- **Journal ≠ memory.** `MEMORY.md` = short behavioral rules auto-loaded into context;
  `notes/sessions/` = full narrative, retrieved on demand. A correction lands in both.
  Keep the two stores independent — neither may depend on the other.
- **Extend `session-record.sh`, don't add a second SessionEnd hook.** It already writes the
  breadcrumb index; add the transcript path + a journal-queue marker there.

## Gotchas / open risks

- **Never block session end.** Stage 1 must inherit the `set -u` / best-effort / always-`exit 0`
  discipline verbatim. A slow or failing journal path must not affect the user.
- **Dirty clone safety.** The summarizer works in the live clone `/Users/galta/Development/gal-va`.
  If it's dirty at run time, ABORT the run and retry next cycle — never stash/reset Gal's changes.
  (`git reset --hard` / `git checkout .` are also blocked by `guard.sh`.)
- **Model routing.** Summarization is read+summarize → use the **fast model (Haiku)** per the new
  subagent-model-routing rule, not Opus.
- **`notes/README.md` must be updated** to document `sessions/` as a second writer
  (`source: claude-code`), or it will look like a rogue directory.
- **Offline handling.** Push failure must leave the local commit intact and exit 0 (retry next run).
