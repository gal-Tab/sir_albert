# W4 — Router scorecard + thin A/B replay

**Classification:** Bounded. One repo, one operator, no data contracts. The unknowns are cost and judging rigor, not feasibility.

## Context

W1–W3 are merged and live (PR #13, `9fc48fc`). The router, bootstrap, global `CLAUDE.md` and the `guard.sh` symlink all work on this machine. W4 is the evidence gate that stands between here and uninstalling `superpowers`.

Two facts about the existing evidence set the shape of this spec:

1. **The W3 recall ground truth is contaminated.** Of the 20 recall examples in `docs/plans/2026-09-24-w3-router/precision-recall-report-2026-09-25.txt`, the "misses" include `go`, `ok contuine`, `1`, and `1 (crosswalk migration) is done and live`. Those prompts preceded a skill invocation because the skill fired *mid-conversation*, not because the prompt should route. A router that fired on `go` would be broken. The headline "33% brainstorm recall" is therefore measured against a label set that is mostly noise, and must not be used as a W4 baseline.
2. **The corpus is effectively unlabeled.** 1,912 of 1,938 rows have `label = null`. The 26 that carry a label spread across 19 skills — one or two examples each — and several name legacy skills (`sir-albert:discovery-lens`, `gtm-planning`, `llm-wiki-agent:learn-capture`). There is no ground truth to score against; it has to be built.

## Goal

Produce a defensible, auditable answer to one question: **is sir_albert good enough on its own that removing `superpowers` costs nothing?** Deliver it for under $40 of replay spend, with every run verifiable from the filesystem.

## Non-goals

- **Uninstalling `superpowers`.** That is a separate, explicit decision by Gal, taken after reading this eval's verdict. It is never inferred from a passing score.
- Fixing the `guard.sh` `git push .*-f` over-broad regex (tracked as a W3 loose end).
- The `gtm_agent` stale `llm-wiki-agent` refs, and pushing `os/preamble-heartbeat`.
- The dapulse org migration.
- Retuning router patterns. P1 *reports* which patterns to fix; the fixes are a follow-on.

---

## The A/B asymmetry (why this is two gates, not one)

`superpowers` has no router. It injects ~650 tokens of `using-superpowers` on `SessionStart` and relies on the model's judgment to pick a skill. sir_albert routes with deterministic regex plus a `SessionStart` context block. **There is no comparable routing number to place side by side.**

So W4 splits:

| Gate | Question | Comparative? | Cost |
|---|---|---|---|
| **P1 — Router scorecard** | Does sir_albert's router hit an absolute quality bar on a trustworthy labeled set? | No — absolute bar on B | ~$0 (offline regex) |
| **P2 — Thin replay** | Given sir_albert's context and no superpowers, does the model invoke a relevant skill and do comparable work? | Yes — A vs B, blind paired preference | ≤$40, capped |
| **P3 — T2 discipline skills** | Do the 5 discipline skills behave under real scenarios? | No | Scoped after P1/P2 land |

P1 is the cheap gate and runs first. A router that misses its bar makes P2 a waste of money — fix patterns, re-score, then spend.

## P1 — Router scorecard (offline, ~$0)

### Labeled set

Gal hand-labels. This is the only trustworthy ground truth available, and it is reusable for every future router change — the cost is paid once.

**The sample is deliberately not uniform.** A uniform 60-prompt sample would contain only ~12 router fires, so precision — the metric that matters most — would rest on a denominator of 12, where a single error swings it 8 points. Gating spend on that is false rigor. Instead the sample is weighted toward where the router actually fires:

| Slice | n | Labeling effort | Feeds |
|---|---|---|---|
| **All known router matches** | 104 | Binary yes/no (+ correct route if no), ~6s each | **Precision**, denominator 104 |
| Random task-initiating prompts | 30 | Full route choice from 10, ~20s each | Recall (indicative) |
| Negative controls (`go`, `yes`, acks, mid-thread replies) | 10 | Binary | False-fire rate |

~144 rows, ~20–25 min, because the bulk are fast binary judgments.

**Revised by Gal, 2026-09-26: partial labeling.** Gal labeled 25 router matches (20/21 correct = 95%, 95% CI 77–99%) and declined the full set. Minimum coverage is ≥21 scored router matches, ≥15 task-initiating (the only source of P2's B-silent and control slices) and all 11 negative controls. The precision gate is decided on the point estimate, and the CI is reported alongside it. Adding ~15 more router matches would lift the CI's lower bound above 80%, which is optional.

- **Source:** `~/.claude/sir-albert-corpus/corpus.jsonl` via the existing validated organic filter in `plugins/sir-albert/tools/prompt_corpus.py` (`is_organic`). Do not write a new sampler.
- **Task-initiating filter:** a prompt qualifies only if, read in isolation with no `preceding_turns`, it states a task. This is the exact property the contaminated W3 label set lacked, and the definition the labeling checklist must enforce.
- **Labels:** one of the 10 route names, `none`, or `ambiguous`. `ambiguous` rows are excluded from scoring but retained — they are the interesting cases for pattern work.
- **Storage (decided by Gal 2026-09-26): labels are committed, prompt text never is.** Gal's prompts come from other repos and include internal monday.com content, and this repo will move orgs.
  - `labels.jsonl` is **committed**, with `_hash`, `slice`, `predicted_route`, `label`, `labeled_by` and `labeled_at` only. It is the durable record of the labeling work.
  - `labeled-set.jsonl` and `labeled-set-checklist.md` hold the text and are **gitignored, local only**. Both can be rebuilt at any time from the local corpus plus `labels.jsonl`, joined by `_hash`, which also survives corpus re-extraction.
  - The same rule covers `sample.jsonl`, `runs/` and `judgments*.jsonl`. Reports quote at most a hash plus 80 chars.

### Pass bar (absolute, on B)

The two error types are not symmetric. A **wrong fire** teaches Gal to ignore every future nudge — the damage compounds and is not recoverable. A **miss** just means Gal names the skill himself, which is exactly what he does today — near-zero cost. So precision is the strict gate and recall is deliberately loose.

| Metric | Bar | Role | Why |
|---|---|---|---|
| Precision | **≥ 80%** | **Gate** | Of prompts where the router fires, the route is the labeled one. Measured over n=104, so the number means something. |
| Recall | ≥ 50% | Diagnostic only | Measured over n=30 — error bars too wide to gate spend on honestly. Reported, not enforced. |
| False-fire rate | **≤ 10%** | **Gate** | On the negative control slice. Firing on `go` is the single failure that discredits the whole router. |

### Match distribution (measured 2026-09-26, current corpus)

102 matches over 1,938 organic prompts — a 5.3% fire rate, reproducing the 104/1,982 figure in the W3 report. But they are not spread evenly:

| Route | Matches | Per-route precision meaningful? |
|---|---|---|
| `plan` | 41 | Yes |
| `brainstorm` | 31 | Yes |
| `handoff` | 15 | Marginal |
| `execute` | 6 | No — under-powered |
| `slack` | 4 | No |
| `design` | 3 | No |
| `attack`, `debug` | 1 each | No |
| `grill`, `zoom-out`, `build`, `resume`, `slack-hebrew`, `linkedin-hebrew` | **0** | **Dead routes** |

Two consequences:

1. **Precision is gated on the overall figure (n=102), not per-route.** Per-route numbers are reported for `plan`, `brainstorm` and `handoff` only; the rest are labelled under-powered rather than given a misleading percentage.
2. **The dead-route list is a first-class P1 output.** Six of fourteen routes never fire on 1,938 real prompts. A route that never fires cannot help Gal regardless of how good its skill is.

**Pre-diagnosis (2026-09-26).** Shadowing by `order` precedence is *ruled out* — each pattern tested in isolation, and only 2 prompts in the whole corpus are shadowed (`zoom-out`→`attack`, `execute`→`plan`). The dead patterns match nothing at all. They split three ways:

| Class | Routes | Evidence | Disposition |
|---|---|---|---|
| **Vocabulary mismatch** — pattern bug | `build` | 86 prompts use "open pr" / "merge" / "push"; the pattern demands "finish the branch" / "ship this feature", which Gal never types | Rewrite in Gal's vocabulary; label carefully, since "yes open pr" is a mid-thread ack |
| **Not regex-routable** | `resume` | Gal's phrasing is "continue" / "resume" — but "continue" is also his most common mid-thread ack; routing it would breach the false-fire gate | Leave to explicit invocation; restart prompts already name `/sir-albert:resume` |
| **Demand absent from corpus** | `grill`, `zoom-out`, `slack-hebrew`, `linkedin-hebrew` | 7 Hebrew prompts of 1,938, none a Slack/LinkedIn draft request; grill/zoom-out probe hits are false positives | Unmeasurable here. Keep/drop is Gal's call, not an eval result |

Corollary: the W3 report's four `slack-hebrew` "misses" were English prompts ("slack in my voice") — another mislabeled row in the contaminated set.

### Output

`docs/plans/2026-09-26-w4-eval/p1-scorecard-2026-09-26.md` — overall precision (the gate), per-route figures for the three powered routes, the dead-route list with a diagnosis per route, confusion pairs, and a ranked list of concrete pattern fixes. **Gate:** if either gate bar is missed, stop. Report to Gal, do not start P2.

## P2 — Thin A/B replay (≤$40, hard-capped)

### Arm isolation — the architectural key

Today `claude` is aliased to `--plugin-dir /Users/galta/Development/sir_albert/plugins`, so whatever is checked out — including uncommitted work — is live in every session, and hooks fire globally. Arms built on install state would not be isolated.

**Native CLI flags do this, verified against `claude --help` on 2026-09-26.** (`CLAUDE_CONFIG_DIR`, an earlier draft's mechanism, is not a documented flag or env var in this build — do not build on it.)

`~/.claude/settings.json` holds both `enabledPlugins` — including `"superpowers@claude-plugins-official": true` — and Gal's user-level `hooks` block, which is where `guard.sh` is registered. That makes the arm switch a one-variable override:

| Arm | Settings | Plugin |
|---|---|---|
| **A — today** | copy of `~/.claude/settings.json`, superpowers `true` | `--plugin-dir` → `/tmp` local clone at a pinned SHA |
| **B — today minus superpowers** | same copy, superpowers `false` | same `--plugin-dir` |

**Arm A carries sir_albert too.** The decision being made is *"uninstall superpowers"* — and Gal's real setup today has both plugins. So the honest counterfactual is today vs today-minus-superpowers. An earlier draft pitted superpowers alone against sir_albert alone; that answers "which plugin is better", a question nobody is deciding. Superpowers is the only variable that differs between arms.

**Verified by probe, 2026-09-26** (`docs/plans/2026-09-26-w4-eval/04-probe-results.md`, $0.32 total):

| | Arm A | Arm B |
|---|---|---|
| superpowers skills loaded | 15 | 0 |
| sir-albert skills loaded | 28 | 28 |
| `using-superpowers` injected | ✅ | ❌ |
| `## sir_albert` SessionStart injected | ✅ | ✅ |
| Model at init | `claude-opus-5-5[1m]` | `claude-opus-5-5[1m]` |

Invoked as `--setting-sources project,local` (excluding `user`) plus `--settings <arm-file>`, so the arm file is authoritative and Gal's live user config is never read.

**Zero mutation of Gal's real setup.** No uninstall, no toggling his live config — the arms are two settings *files*. Reversible by construction, and arm A is faithful to his actual environment because it is literally a copy of it, with exactly one variable changed.

**Four native flags replace hand-rolled machinery:**

| Flag | Replaces |
|---|---|
| `--setting-sources` + `--settings` | per-arm config dirs; arm isolation |
| `--no-session-persistence` | snapshot/redirect of `sir-albert-sessions.jsonl`. Nothing is written at all, so corpus pollution is **eliminated**, not mitigated |
| `--max-budget-usd` | cost-extrapolation abort logic. A CLI-enforced hard cap |
| `--output-format json` | parsing stdout for cost and turn count |

**Model under test: `claude-sonnet-5` (Sonnet 5), for both arms and the judge — revised by Gal 2026-09-26** (originally Opus 5.5). The verdict therefore describes Sonnet sessions; Opus may follow skill-use instructions differently. Gal's default (`claude-opus-5-5[1m]`) is a separate value, protected by the guard and never used for runs. ~~Originally: Opus 5.5.~~ The harness asserts the model at start equals this value and aborts otherwise. That way a drifted default can't silently change what is being measured.

`--model` is set explicitly per run rather than inherited, and **is identical across both arms**. The value is read once from `~/.claude/settings.json` at harness start and recorded in every run artifact — it is never hardcoded (Gal changes his default; on 2026-09-26 it moved from `claude-opus-5[1m]` to `claude-opus-5-5[1m]` mid-session).

**`guard.sh` is preserved automatically** — because each arm's settings file is a *copy* of `~/.claude/settings.json`, the `hooks` block comes along with it. This matters: excluding `user` sources would otherwise drop guard.sh and run the replay unprotected.

**Clone, not worktree.** Worktrees share the object store and refs with the real repo, so a stray `git` command inside a replay run could delete branches or move refs in `~/Development/sir_albert`. A local clone is a hard boundary.

**Ticket 04 must empirically verify** `--setting-sources`/`--settings` precedence (the latter is documented as loading *additional* settings), that superpowers is genuinely absent in B and present in A, and that `--no-session-persistence` and `--max-budget-usd` behave as documented. Use `command claude` to bypass the zsh alias.

**Model-reset guard: the PRIMARY defence.** An earlier draft claimed excluding `user` settings made the footgun impossible. **The probe disproved that.** Root cause, verified 2026-09-26: `claude` on this machine is `~/.axcli/bin/claude`, a two-line wrapper that execs `axcli spawn`. The string `Default model set to` is compiled into the axcli binary itself, and it rewrites `"model"` in `~/.claude/settings.json` to `claude-sonnet-5` on **every spawn** — including `--help` and `--version` — regardless of `--model` or `--setting-sources`. No Claude Code flag can prevent it.

Therefore:

- **Every spawn goes through a guard** that snapshots the model, runs, and restores on `trap EXIT`. Proven in the probe: drift `claude-sonnet-5 → restored claude-opus-5-5[1m]`, file valid JSON, no other key touched. A reference implementation is in the probe results.
- The restore is a single-line regex replacement, asserting exactly one match and re-validating JSON — never a `json.dump` rewrite of Gal's file.
- **Runs are sequential**, never parallel: the guard restores per run, and concurrent spawns would race on the file.
- **Residual window:** while a run is in flight, `settings.json` says `claude-sonnet-5`. A session Gal opens during a tranche would start on Sonnet. Tranches are announced before they start.
- **The expected value is the snapshot taken at harness start, never a constant.** A hardcoded expectation would "restore" Gal to a stale model the moment he changes his default.
- The axcli behaviour is worth reporting to the axcli owners. Draft only — an external send.

**Other side effects verified:**

- `--no-session-persistence` works: no transcript is written (an empty `~/.claude/projects/-private-tmp-…` dir is created, which `prompt_corpus.py`'s `*.jsonl` glob ignores).
- **It does not stop hooks.** sir_albert's own `SessionEnd` hook appends one row per run to `~/.claude/sir-albert-sessions.jsonl`. With sir_albert in both arms, a 60-run replay adds 60 rows. The harness backs the file up, then strips only rows whose `cwd` is under its scratch dir.

### Canary preflight (abort gate)

Hooks silently not firing is the documented failure mode here — `hooks.json` was missing its `{"hooks":[...]}` wrapper for an entire workstream, undetected. Measuring arm B with a dead router would hand the win to `superpowers` on a bug.

Before any scored run, per arm:

- **Arm B:** run a canary prompt known to route (`write handoff`). Assert the `SessionStart` injection text *and* the `UserPromptSubmit` nudge both appear in the transcript.
- **Arm A:** assert `using-superpowers` text appears in the transcript.
- **Either fails → abort the entire replay.** Do not degrade to a partial run.

### Sample

N=15, drawn from the P1 labeled set, deliberately stratified to include B's weak spots rather than only its wins:

| Slice | n | Rationale |
|---|---|---|
| B routes, label agrees | 5 | B's happy path |
| Label says route, B is silent | 5 | B's known weakness — the honest test |
| `none` / `ambiguous` | 5 | Control; catches over-firing and confabulated skill use |

Random sampling is wrong here: the router's fire rate is 1.4–5.2%, so most organic prompts produce no routing difference at all and would buy nothing.

**Exclusion: prompts containing file/path references (14% of the corpus).** Only 38 of 1,938 corpus prompts originate in `sir_albert` — 821 come from `gtm_agent`, 269 from `open-claw`. A prompt saying "read `docs/HANDOFF.md`" will not resolve against a scratch clone. Paired preference tolerates *symmetric* degradation, but there is no reason to buy the noise when 86% of the corpus is self-contained.

### Run configuration

- **k=2** reps per prompt per arm → 15 × 2 × 2 = **60 runs**.
- **Write tools disabled:** `--disallowedTools Write,Edit,NotebookEdit`.
- **Bash and Read stay enabled — this is a fairness requirement, not a fidelity nicety.** Every sir_albert skill opens with *"Boot from `os/PREAMBLE.md`"*, so it must read files out of the plugin dir to function at all. superpowers skills are self-contained text blocks. Disabling read/exec tooling would cripple arm B asymmetrically and hand arm A a win it did not earn. Containment is the `/tmp` local clone plus `guard.sh` in both arms.
- **Per-run ceiling:** `--max-turns 12`.

### Artifacts — auditability is a requirement, not a nicety

The documented recurrent failure mode is builders faking evals: the W2 builder faked T2 twice by batching or role-playing reps instead of making real agent calls. The recorded rule is that **the number of agent calls must ≈ reps × conditions + judges**.

One file per run: `docs/plans/2026-09-26-w4-eval/runs/<arm>-<prompt_hash>-rep<k>.json`, containing raw stdout, exit code, timestamp, cost, turn count, and the skills invoked.

`ls runs/ | wc -l` **must equal 60.** The verdict is rejected if it does not. No judge table is accepted without its underlying transcripts. Reports are namespaced `<name>-<date>-<runid>` — a prior eval report was destroyed by a filename collision when `04c` overwrote `04b`.

### Judging — blind paired preference

Labels cannot score *output quality*, only routing. So quality is judged comparatively, with the judge blind to condition.

- Pair rep-wise: `A/rep1` vs `B/rep1`, `A/rep2` vs `B/rep2` → 30 pairs.
- Judge sees the prompt plus the two final responses, with arm-identifying strings redacted (`superpowers:*`, `sir-albert:*`, `kb:*` → `[skill]`) and truncated to 1500 chars. It does **not** know which arm is which.
- **Skill names are never shown to the judge.** `superpowers:*` only exists in arm A, so showing them would unblind it. Skill invocation is scored separately in the verdict, from `Skill` tool_use events (`skills_called`), never from the init event's loaded-skills list.
- Judge runs under **neutral settings**: all plugins off, no hooks, no tools, through the model guard. Otherwise the superpowers injection would sit in the judge's own context.
- **Empty responses and unparseable judge output are errors, never ties.** Scoring them as ties pulls B toward 50% and passes the 40% gate by default.
- **Position bias control:** each pair is judged twice with the order swapped → 60 judge calls. These are text-only, no tools, so they are cheap.
- Judge outputs winner (`left` / `right` / `tie`) plus a one-line reason. A pair where the two orderings disagree is recorded as a tie.
- "Which skill fired" is captured as an **observed variable**, not a target.

### Verdict rule

B passes if **both** hold:

- Paired-preference win rate for B ≥ **40%** (ties split). The claim being tested is "not materially worse", not "better" — B only has to be good enough to make removing A free.
- B invokes a relevant sir_albert skill on ≥ **4 of the 5** happy-path slice prompts.

### Budget cap

- **Hard cap: $40** for all of P2, enforced two ways.
- **Per-run ceiling via `--max-budget-usd 0.60`**. The CLI enforces it, so no run can overshoot, whatever the harness logic does. 60 runs × $0.60 = $36 worst case, which leaves ~$4 for the 60 text-only judge calls. A run that hits the ceiling is flagged `budget_capped` in its artifact and reported. The cap is the same for both arms, so it truncates them the same way, but if it fires often the pilot should raise it.
- **Probe baseline:** a trivial 1-turn prompt cost $0.08–$0.14 per arm. Differences at that size come from prompt caching, not from the arm, so they don't indicate one arm's context is heavier.
- **Tranche-level accounting** as the second layer. Tranche 1 = 10 prompts (40 runs) — the cost pilot, which **requires Gal's explicit yes before it runs**. Measure the real `axcli usage` delta on completion and report it.
- Tranche 2 = the remaining 5 prompts (20 runs), and only if tranche 1's measured cost leaves the total inside the cap.
- Current headroom: $382.81 of the $750 monthly budget.

## Approaches considered

| Approach | Verdict |
|---|---|
| **Routing bar + thin replay** (chosen) | Puts the cheap gate first and only spends money on the question a replay can actually answer. Requires ~20 min of Gal's labeling time. |
| Full output-quality A/B replay, ~50 prompts, k=2 | $60–200. With contaminated labels the judge becomes the sole signal, so all rigor rests on judge design. Rejected as expensive and less diagnostic — it would not tell us *which patterns to fix*. |
| Behavioral parity only, no judging | Near-free and binary, but asserts nothing about whether the resulting work is any good. Too weak to justify an uninstall. |

On the labeled set: the alternative was a Haiku pre-labeling pass with Gal adjudicating. Rejected — the labeler and the thing under test share a failure mode, so agreement could be illusory. Reusing the existing 20 examples, filtered for genuinely task-initiating prompts, leaves ~8–12 rows: too few to score against.

## Resolved decisions (2026-09-26)

1. **Bash during replay: ON.** Decided on fairness grounds, not fidelity — sir_albert skills cannot boot their own preamble without read tooling, so disabling it would bias the eval against arm B. Contained by the `/tmp` local clone and `guard.sh` in both arms.
2. **P1 bars: precision ≥80% as the gate, recall ≥50% as a diagnostic.** The original 70/60 pair was both backwards (it treated the two error types as symmetric when a wrong fire is far more costly than a miss) and unmeasurable (precision over a denominator of ~12). Fixed by weighting the labeled set toward router matches.

## Risks

| Risk | Mitigation |
|---|---|
| `--settings` / `--setting-sources` precedence differs from assumption | ✅ Verified by probe 2026-09-26: arm switch works, superpowers present/absent as intended |
| axcli rewrites Gal's default model on every spawn | Guard on every spawn, sequential runs, restore on `trap EXIT` — proven in probe |
| Arm B's hooks silently dead → false loss for sir_albert | Canary preflight, abort on failure |
| Builder fakes runs | 60 artifact files, `ls \| wc -l` check, verdict rejected without transcripts |
| Session-record pollution corrupts future corpus extraction | `--no-session-persistence` (verified: no transcripts); sir_albert `SessionEnd` rows stripped by cwd after each tranche |
| Runaway run blows the budget | `--max-budget-usd`, enforced by the CLI |
| Replay `git` command damages the real repo's refs | `git clone --local` into `/tmp`, never a worktree |
| Replay runs execute unguarded | Arm settings are copies of `~/.claude/settings.json`, so the `hooks` block carrying `guard.sh` is preserved |
| Labeling fatigue → sloppy ground truth | 104 of the 144 rows are ~6s binary judgments; single pass, resumable |
