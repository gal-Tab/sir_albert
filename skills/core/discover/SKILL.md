# Discover

Boot from `os/PREAMBLE.md`.

## Purpose

Discover is the **front door to thinking** — a Core phase (mode-agnostic) that runs before committing to a GTM, Building, or Automation task. Its job is to pick the right lens, not to execute. Getting this wrong costs more than the time it takes to do it right.

The empirical case: "WDYT?" ×43 and option-picking moments ×77 across sessions show this phase is constantly happening but inconsistently routed. This skill names it and routes it.

---

## Routing table

Read the situation, pick one route. Offer the match and ask to confirm before loading the skill.

| Situation | Route to |
|---|---|
| Explore an idea / fresh AI-first perspective | `discovery-lens` |
| Want multiple independent viewpoints | `board-of-advisors` |
| Attack / challenge / find holes | `devils-advocate` |
| Stress-test my thinking (interview me) | `grilling` — or `grill-with-docs` when there are docs to sharpen against |
| Bigger picture / how does this fit | `zoom-out` |
| Pin down terminology / record an ADR | `domain-modeling` |
| Sanity-check a UI or state model quickly | `prototype` |

If the situation matches more than one row, surface the top two and ask which matters most right now.

---

## Discover is a phase, not a pack

It precedes execute/build tasks — it does not replace them. Once a lens is chosen and the thinking has produced a clear direction, Discover is done. Hand off to the appropriate working skill (e.g. `to-prd`, `domain-modeling`, `prototype`, or a biz/dev/agentic skill).

Do not linger here. The goal is a sharper starting point for the next thing, not a permanent mode.

---

## How to run

1. Ask one clarifying question if the situation is ambiguous: "Are you trying to explore this fresh, stress-test a formed view, or just figure out where to start?"
2. Name the matched lens and why.
3. Load the skill and hand off.

Keep this interaction tight — two or three turns maximum before routing.
